## Lessons learned (Phases 0–5)

- **Measure, don't assume.** Token estimates were off by 2–3× twice (Groq 120b judge, qwen's hidden thinking); measure one real question with `langchain_core.callbacks.get_usage_metadata_callback` before any full eval run.
- **Screen retrieval changes for free first.** ID-based context precision/recall need no LLM; the offline replay reproduced the paid eval exactly and showed no reranker beats hybrid before any credit was spent.
- **Rerankers don't transfer automatically.** MS MARCO / general rerankers (MiniLM L-6/L-12, mxbai-xsmall, bge-reranker-base) all ranked this corpus's K8s chunks worse than dense + BM25 RRF. A code-trained one (gte-reranker-modernbert, fused with the hybrid order) beat hybrid by +0.07 precision, but at 13–27 s/query on CPU — training data matters, and so does latency.
- **Hybrid beats dense** on this noisy corpus (+0.079 context precision): BM25 catches exact tokens (`kubectl rollout undo`) that embeddings miss.
- **Make long jobs resumable.** Ingest (`--skip-existing`) and evals (checkpoints) survive kills; the laptop's 7.3 GB RAM gets background jobs killed.
- **Keep eval settings fixed across a comparison** (same questions, judge, judge settings, metric definitions); when one changes (E1's judge thinking, q-017/q-018 re-tagged), record which metrics stay comparable and compare on the same question IDs (computed free from the result files).
- **Averages hide failure modes.** E3 `all` was best on every metric, yet CRAG + general web wrote a poem and an insulting message, and gave dictionary definitions for vague questions: read the per-question answers, not just the table.
- **Don't let the LLM do logic code can do.** gpt-oss twice judged "Sept 2026 is inside 2025-05..2026-05"; the data-end note is now added in code. Same idea: SQL safety is sqlglot + a read-only role, not a prompt.
- **A feature that never triggers is just cost.** Self-RAG made 0 retries in E3 (it waited for a refined question the grader never gave) while costing a call per question; check that a feature actually fires before keeping it.
- **A cache key must hold everything the result depends on.** The Phase 5 review found keys missing the pipeline settings, today's date (SQL) and the case of quoted SQL values: each one would silently serve a wrong cached answer. When a prompt or setting changes the output, it belongs in the key.
- **Don't trust a side record over the real store.** The dedup records in `./cache` outlive Qdrant (`down -v`); "already ingested" must check Qdrant itself.
- **Plan TTLs around the eval schedule.** E5's cold run was stopped for low memory, and its first 29 cached answers (3 h TTL) expired before the warm run, so a refill pass was needed; and a metric's name must match what it counts (the first answer-cache hit rate counted SQL rows that still called the LLM).
- **The judge alone moves faithfulness by ~±0.05** on identical answers (E5: q-034 1.0 → 0.44 with the same text); compare on the same question IDs and the same answers before calling a regression.
- **Metrics need the right context.** SQL answers with correct numbers scored 0 faithfulness because the judge saw rows without the query; Ragas also scores correct declines ~0. Judge what you can verify, and record the artifact.

### `app/`

- `config.py` — `Settings` with a typed field for every `.env` var, plus `api_host` / `api_port` / `api_workers` (defaults `0.0.0.0` / `8000` / `1`). Secrets are `SecretStr` (use `.get_secret_value()`). `CEREBRAS_API_KEY`, `DATABASE_URL`, `JWT_SECRET` are required, and `JWT_SECRET` must be ≥ 32 chars or startup fails (`field_validator`). `SEED_ADMIN_PASSWORD` / `SEED_ANALYST_PASSWORD` are optional (used only by the seed script). (Pylance flags `Settings()` as missing args — suppressed with `# pyright: ignore[reportCallIssue]`, it's a false positive). Fixed choices are `Literal` (`STORAGE_BACKEND`, `RERANKER_BACKEND`, `LOG_LEVEL`, `LLM_REASONING_EFFORT`). Import `settings` or `get_settings()`. LLM settings: `CEREBRAS_API_KEY`, `CEREBRAS_BASE_URL` (`https://api.cerebras.ai/v1`), `LLM_MODEL_ANSWER` / `LLM_MODEL_GRADER` (`gpt-oss-120b`), `LLM_REASONING_EFFORT` (`low`), `EVAL_JUDGE_MODEL` (`qwen-3.8-27b`), `EVAL_RELEVANCY_STRICTNESS` (1 from E3 on; E1/E2 used 3). Retrieval: `RRF_K` (60), `RERANKER_BACKEND` (`local`), `RERANKER_MODEL` (`cross-encoder/ms-marco-MiniLM-L-6-v2`), `RERANKER_MAX_LENGTH` (256), `RERANKER_INITIAL_TOP_K` (20). Default flags come from `HYBRID_SEARCH_ENABLED` (true → `hybrid`, false → `dense`), `RERANKING_ENABLED_BY_DEFAULT` (false), `HYDE_ENABLED_BY_DEFAULT` (false), `CRAG_ENABLED_BY_DEFAULT` (true), `SELF_REFLECTIVE_ENABLED_BY_DEFAULT` (false), read by `rag_service._default_flags()`.
- `main.py` — `lifespan` uses an `AsyncExitStack` so everything opened is closed even if startup fails midway. Shared clients on `app.state`: `db_pool` (psycopg3 `AsyncConnectionPool` with explicit `connection_class=AsyncConnection` so type checkers resolve the pool type; opened with `wait=True, timeout=10` so startup fails fast if Postgres is down), `qdrant` (`AsyncQdrantClient`), `redis` (from `get_redis_client()`, or `None` if Upstash isn't configured), `llm` (`AsyncOpenAI` pointed at `CEREBRAS_BASE_URL`). Creates the `users` table on startup by running `seed/migrations/001_create_users.sql` (the only definition of that table), runs `vector_store.ensure_collection()`, and warms the BM25 index (a failure is only logged; the index then builds on the first sparse/hybrid query). Qdrant and LLM clients come from `vector_store.get_client()` / `llm_service.get_client()`; on shutdown they're closed and their caches cleared. Routers: auth, admin, query, documents. On shutdown it closes the Redis client and clears `get_redis_client`'s cache so a later startup gets a fresh client. Configures loguru from `LOG_LEVEL` / `LOG_JSON`.
- `middleware/auth.py` — single source of auth logic: `User` (id, username, is_admin), `hash_password` / `verify_password` (passlib bcrypt, 12 rounds, ~250 ms of CPU — call them via `asyncio.to_thread` in async routes), `create_access_token(user_id, username, is_admin, expires_minutes=None)` (payload `{sub: str(user_id), username, is_admin, iat, exp}`, HS256 — `sub` must be a string per the JWT spec), `get_current_user` (HTTP Bearer → `User(id=int(sub), ...)` from token claims, no DB hit; 401 if missing/invalid/expired/tampered), `require_admin` (403).
- `middleware/rate_limiter.py` — `get_redis_client()` (cached Upstash async client, shared with `main.py`), `RateLimiter(max_requests, window_seconds, name=...)`, and `rate_limit_by_ip(limiter)` FastAPI dependency (429 + `Retry-After`; `X-RateLimit-*` headers on success). Sliding window: one sorted set of timestamps per key (`ratelimit:{name}:{ip|user}:{id}`); ZREMRANGEBYSCORE + ZADD + ZCARD + EXPIRE + ZRANGE go in one Upstash pipeline (one HTTP request); `exec()` results are loosely typed, so they're `cast`/`int()`-ed explicitly. `is_allowed` / `is_allowed_ip` / `is_allowed_user` → `RateLimitResult(allowed, remaining, count, retry_after)`. Rejected requests also count. Fails open if Redis errors or takes longer than `REDIS_TIMEOUT_SECONDS` (2 s; the Upstash client has no timeout of its own, and its retry is disabled). Limiters resolve the client per call (`RateLimiter.redis` property), never caching a closed one. If Upstash isn't configured, the same sliding window runs in memory (`_memory_windows`, per process — not shared across workers/restarts; tests use it).
- `api/auth.py` — `POST /auth/register` (JSON; username 3–64 chars `[A-Za-z0-9_.-]`, password 8–72; returns the new user, not a token; 409 on duplicate; 3/hour per IP), `POST /auth/login` (JSON `LoginRequest {username, password}` — form data is rejected with 422; returns `{access_token, token_type, expires_in}`; unknown user and wrong password give the same 401 and take the same time — unknown users are checked against a dummy hash; bcrypt runs in a worker thread; 5/min per IP), `GET /auth/me` (full user row from DB, looked up by the token's user id). `get_pool` returns the pool; routes borrow a connection with `async with pool.connection()`.
- `models.py` — `RetrievedChunk(text, source, score, metadata)`, `RetrievedChunkPreview.from_chunk` (200-char snippet), `ResponseMetadata(intent, flags_used, latency_ms, tokens_used, cache_hits, model)`, `ChatResponse(answer, sources, confidence=None, chunks, metadata)`, `QueryRequest(question 1–2000 chars, flags: QueryFlags)`. `QueryFlags` validates every flag (`extra=forbid`; `top_k` 1–20 = `MAX_TOP_K`; real booleans, so `"false"` → False; `search_mode` in `SEARCH_MODES`); bad flags → 422 at the API, `ValueError` → 400 from `rag_service.validate_flags`. `confidence` stays None until real graders exist (Phase 3) — never hard-code it.
- `services/llm_service.py` — the only LLM caller (Cerebras via the `openai` SDK). `get_client()` is an `lru_cache`d `AsyncOpenAI` (max_retries=6: the SDK backs off on 429 and honours Retry-After; timeout 60 s), shared with `main.py`. `generate(system, user, model=None, temperature=0, json_mode=False)` → `{content, model, usage}`; `generate_with_json` → `{data, model, usage}` (raises `LLMJSONError`; returns usage too because Phase 6 sums actual tokens). Sends `reasoning_effort=settings.llm_reasoning_effort` (`LLM_REASONING_EFFORT`, default `low`) only to gpt-oss models (`is_reasoning_model`); optional params are omitted rather than sent as JSON null. Cerebras returns gpt-oss reasoning in a separate field, never in `content`.
- `services/embedding_service.py` — `get_model()` loads bge once (cuda if available, else cpu), **local cache first** (`local_files_only=True`, network only if not cached — DNS here is flaky). `embed_texts` (async, runs in a thread; normalised vectors) / `embed_texts_sync` (seed script) / `embed_query` (prepends the bge query instruction `"Represent this sentence for searching relevant passages: "` — queries only, never documents).
- `services/vector_store.py` — `get_client()` cached `AsyncQdrantClient` shared with `main.py` (`app.state.qdrant`). `ensure_collection()` (768-dim cosine + keyword index on `source`; run at startup), `upsert_chunks()` (point ID = uuid5(source::chunk_index): re-ingesting overwrites, never duplicates; batches of 256), `search()`, `delete_source()`, `list_sources()` (facet on `source`; needs server Qdrant — local `:memory:` mode ignores payload indexes), `count_points()`. **Phase 2:** a module-level BM25 index (`_build_sparse_index`) built once from **all** points (`_scroll_all_payloads`, pages of 1,000, no cap, no vectors), guarded by an `asyncio.Lock`, fitted in a worker thread; ~4.8 s and ~94 MB RAM for 7,285 chunks. `upsert_chunks` and `delete_source` call `invalidate_sparse_index()` so the next query rebuilds. `sparse_search(query, top_k)`; `hybrid_search(query, embedding, top_k)` = dense + BM25, each `max(top_k, RERANKER_INITIAL_TOP_K)` deep, merged with `fuse_rrf(k=RRF_K)`. The index lives per process: after a bulk ingest by the seed script, restart the API.
- `services/sparse_vector_service.py` — `_tokenize` (lowercase; K8s names kept whole by `[a-z0-9]+(?:[-_.][a-z0-9]+)*` — `kube-proxy`, `v1.34` — plus their parts, so "proxy" matches `kube-proxy`; small stopword list), `SparseVectorIndex` (`fit(docs)`, `search(query, top_k)`; rank-bm25 `BM25Okapi`; chunks with score 0 are dropped), `chunk_id` (`source::chunk_index`, same identity as Qdrant point IDs), `fuse_rrf(dense, sparse, k, top_k)` (score = Σ 1/(k + rank + 1), copies chunks, keeps `dense_rank` / `sparse_rank` in metadata). BM25 gotcha: a word in ≥ half the docs gets ~0 weight, so tiny test corpora need filler docs.
- `services/reranking.py` — `Reranker(backend)`: `local` = sentence-transformers `CrossEncoder(RERANKER_MODEL, max_length=RERANKER_MAX_LENGTH)` loaded lazily, local HF cache first; `voyage` = `voyageai.client.Client` (`VOYAGE_MODEL` rerank-2.5). `rerank(question, chunks, top_k)` returns the best `top_k` with the rerank score as `score` and the old one in `metadata["retrieval_score"]`; **fail-soft**: on any error it logs the exception type and returns the first `top_k` unchanged. `get_reranker()` is an `lru_cache` singleton. Measured on this CPU (20 candidates): ~1.1 s at 256 tokens, ~3.6 s at 512. Voyage without a payment method allows 10k tokens/min — one 20-chunk rerank is ~9.4k, so it falls back most of the time.
- `services/document_processor.py` — `DocumentProcessor(table_structure=True)`: Docling with **OCR off** (corpus PDFs are born-digital), `HybridChunker` with the bge tokenizer, max 512 tokens, `merge_peers=True`; chunk text = `chunker.contextualize()` (heading path + text). `.txt` has no Docling reader, so it's fed as an in-memory `.md` stream (source keeps the `.txt` name). `process_document(path, source=None, max_pages=None)` → `[{text, source, metadata{chunk_index, headings, page}}]`; `max_pages` → Docling `page_range`. Measured on this CPU: PDF ~2.3–2.8 s/page (tables off only saves ~20%), html 0.3 s, docx ~2 s; ~1.8 chunks/page, ~1.5k chars/chunk.
- `services/rag_service.py` — `DEFAULT_FLAGS = _default_flags()`, built from the settings at import: **hybrid + CRAG on, top_k 5, rerank/HyDE/Self-RAG off** (user's choice after E3, 2026-10-23). A request overrides any flag (e.g. `{"enable_crag": false}`); eval profiles pass every flag, so they don't depend on the defaults. Streamlit's toggles start from `GET /query/defaults` because the UI always sends every flag. (Until E3 the defaults were the `naive` flags); `_flag()` safe read; `_retrieve`: `search_mode` `dense` | `sparse` (BM25, no embedding) | `hybrid`; unknown mode → `ValueError` → 400. Without rerank it fetches `top_k` directly (so `naive` is **exactly** the Phase 1 path E1 measured — `test_naive_profile_is_exactly_the_phase1_path` guards it); with `enable_rerank` it fetches `max(top_k, RERANKER_INITIAL_TOP_K)` candidates and the reranker (in a worker thread) keeps `top_k`. Other flags (`enable_hyde`, `enable_crag`, `enable_self_reflective`) are **ignored until Phase 3**. `_build_context` numbers chunks `[n] (source: x)`; `_generate`; `run_rag_with_trace` returns `(ChatResponse, full chunks)`; no chunks → `NOT_FOUND_ANSWER` without an LLM call; sources deduped in retrieval order; `metadata.flags_used` lists the `DEFAULT_FLAGS` keys.
- `services/passages.py` — `format_passages(chunks, max_chars=None, with_sources=False)`: the one `[n]` passage formatter (answer prompt with sources; CRAG cut to 1,200 chars; Self-RAG whole chunks). Phase 6 spotlighting replaces it in one place.
- **Phase 3 (user's choices 2026-10-23: build on `hybrid` without rerank; in-app grader `gpt-oss-120b` = `LLM_MODEL_GRADER` so the eval judge (qwen) stays independent; general-web Tavily search).**
  - `services/hyde.py` — `HyDERetriever(num_hypotheses=HYDE_NUM_HYPOTHESES=3)`, one per request (keeps `hypotheses`, `tokens_used`). `generate_hypotheses` = one JSON-mode grader call (`{"hypotheses": [...]}`), fail-soft → []. `retrieve(question, top_k)` = dense search for the question (with the bge query instruction) + each hypothesis (embedded as documents), merged with `sparse_vector_service.fuse_many` (RRF over N lists), deduped on normalised text. In `rag_service` HyDE replaces the **dense part**: with `hybrid`, HyDE results (20 deep) are RRF-fused with BM25 on the question; ignored for `sparse`.
  - `services/web_search.py` — cached `AsyncTavilyClient` (None without `TAVILY_API_KEY`); `search_web(query, max_results=5)` → chunks with `source` = URL, `metadata.origin="web"` (`is_web_chunk`); never raises (no key / error → []). 1 credit per search ("basic"; free plan 1,000/month).
  - `services/crag.py` — `grade_chunks` = one JSON-mode grader call scoring each chunk 0–1 (chunks cut to 1,200 chars, `format_passages`) **and** deciding `kubernetes_related` (→ `CRAGEvaluation.in_scope`; it runs even with 0 chunks so the scope is known), `max_score` → `correct` (≥ `CRAG_RELEVANCE_THRESHOLD` 0.7) / `ambiguous` (≥ `CRAG_AMBIGUOUS_THRESHOLD` 0.5) / `incorrect`; a failed call → `ungraded` (chunks kept; tokens of a bad-JSON reply still counted). `crag_pipeline`: correct → chunks scoring ≥ 0.5 (score in `metadata.crag_score`); **web only for in-scope questions** (user's rule 2026-10-26: Kubernetes / containers / cloud-native tools / IT-ops of running them, any version): ambiguous → those + web; incorrect → web only; **web empty → original chunks kept**. Off-topic (`in_scope` False): ambiguous → relevant chunks, no web; incorrect → **no chunks**, and `rag_service` answers `OUT_OF_SCOPE_ANSWER` without an answer call. Scope unknown (grader left it out) → no web, original chunks kept. The same call also returns `too_vague` (no clear subject/goal: "explain", "what is wrong") → **never searched on the web** (E3's dictionary answers); ambiguous → relevant chunks, incorrect → no chunks and `rag_service` answers `CLARIFY_ANSWER` (asks for the resource, goal, error); checked before the off-topic rule. Live 2026-10-26: q-044 poem, q-043 insult, q-017 weather → `OUT_OF_SCOPE_ANSWER`, no web; K8s 1.34 → web (kubernetes.io blog); "what is wrong" → `CLARIFY_ANSWER`.
  - `services/self_reflective.py` — (user's design 2026-10-26) `reflect_on_answer(question, answer, chunks, refined_question=None)` = JSON-mode grader over the **whole** chunks scoring **relevance, accuracy, completeness, clarity** (0–1 each); `score` = their mean. The prompt caps relevance/completeness at 0.5 for questions too vague to know what the user wants, judges a retry against the clarified question, and must give a `refined_question` when the mean is below the bar. **Fails closed** (error → score 0, "reflection unavailable"). `refine_question` = fallback rewrite call when the grader gave none (fail-soft → no retry). `should_regenerate` = score < `REFLECTION_MIN_SCORE` **0.8** (was 0.85) and retries < `MAX_REFLECTION_RETRIES` 2.

## Evaluation

Every eval run is recorded here (protocol: `plan.md` §2). faithfulness and answer_relevancy are judged by Cerebras `qwen-3.8-27b` (`settings.eval_judge_model`, a different model family from the `gpt-oss-120b` answer model); context_precision / context_recall are computed from source file names (`post_checks.id_context_scores`, 0 tokens); answer_relevancy uses the local bge embeddings (`BAAI/bge-base-en-v1.5`). Log dates are **UTC** (from the result file's timestamp).

Harness notes (`eval/ragas_adapter.py`; first verified 2026-10-22 with Groq, now running on Cerebras):
- The reference answer (`ground_truth`) is the **bare keyword list** (user's choice: goldens have no reference answers). Phrasings like "A correct answer covers: ..." made context_recall always 0; the bare list scores 1.0 on a matching context and 0.0 on an unrelated one. Recall/precision are still rough with keyword references.
- `LangchainLLMWrapper(ChatOpenAI, bypass_n=True)`: separate calls instead of `n > 1` (answer_relevancy needs 3), which not every provider supports.
- `BgeEmbeddings` wraps sentence-transformers directly: ragas 0.4.3's `HuggingfaceEmbeddings` can't be instantiated. Its loaded model attribute is `encoder`, because Ragas expects `.model` to be a string.
- `langchain-community<0.4` is pinned because ragas 0.4.3 imports a module removed in 0.4.
- Failed judgements are stored as `null`, never invented; aggregates ignore them.
- **Checkpoint/resume** (added after E1 attempt 1 lost everything): `run_ragas` saves to `eval/results/checkpoints/<profile>.json` (gitignored) after every answered and every scored question, scoring one question at a time. Re-running the same command resumes: answered questions aren't asked again, and only rows that are unscored, scored by another judge, or have a `null` metric are re-judged. If every metric of a question comes back empty (e.g. the judge's daily limit), it stops with exit code 2 and keeps the checkpoint. `--fresh` ignores the checkpoint. If any question errored (e.g. the answer model hit its daily limit), no result file is written (exit code 3) and the checkpoint is kept, so a re-run asks only those; `--allow-errors` writes a result anyway. The checkpoint is deleted when the result file is written. The checkpoint key includes the answer model, so changing it starts the answers over. Answers cost ~2.5k `gpt-oss-120b` tokens each; a 35-question run takes ~16–19 min (≈ 7 min answering at 5 requests/min + ≈ 9 min judging).
- **answer_relevancy strictness** = `EVAL_RELEVANCY_STRICTNESS` (`settings.eval_relevancy_strictness`; Ragas default 3 = the judge writes 3 guessed questions per answer). E1 and E2 ran with **3**; from **E3 on it's 1** (user's choice 2026-10-23, to save ~15-20% of judge tokens). `.env` was switched to 1 after E2 finished (2026-10-23). Each result file records it as `answer_relevancy_strictness`. Measured judge cost with thinking off and strictness 3: ~7.5k tokens/question (5.3k in, 2.2k out) ≈ $0.30 per 35-question run.
- A gpt-oss judge gets `reasoning_effort=settings.llm_reasoning_effort` (`low`; Groq's default cost ~3.3k tokens per judge job). qwen gets `reasoning_effort="none"`: on Cerebras it thinks silently by default (113 vs 8 output tokens on a tiny judge call), and every token is deducted from the free trial's **$5 credit** (qwen ≈ $0.99/M input, $1.49/M output per one aggregator). E1 was judged with thinking on (see the Baseline caveat).
- **Metric change (2026-10-22, user-approved "option 1")**: context_precision / context_recall are ID-based, from the source file of each retrieved chunk vs `golden_sources` (`context_sources` is stored per row, in rank order). precision is rank-aware like Ragas' (mean precision@k at relevant ranks), recall = fraction of golden files retrieved; both `null` for goldens without sources. The LLM versions cost ~11k of ~17k judge tokens per question.
